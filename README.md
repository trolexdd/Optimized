# Лабораторная работа №2. Числовые ребусы

## Запуск

```
gcc -O0 opt.c -o opt
./opt tests.txt
```

Для каждого ребуса выводятся среднее время решения (по 20 запускам), решение и в конце суммарное время `TOTAL`.

## Оптимизации

Каждая оптимизация сделана отдельным коммитом.

| № | Коммит | Что сделано | Тип оптимизации |
|---|--------|-------------|-----------------|
| 0 | `baseline: brute force` | Перебор всех перестановок цифр, проверка суммы в конце | — |
| 1 | `fix: memset(used) typo, add timing harness` | Исправлена опечатка в `solve`, добавлены замеры времени | исправление |
| 2 | `opt: prune leading zeros during permutation` | Первой букве слова не присваивается цифра 0 при самом переборе | алгоритмическая (отсечение ветвей) |
| 3 | `opt: precompute letter weights, check sum(coef*digit)==0` | Для каждой буквы заранее считается вес (разряд со знаком), проверка сводится к одной сумме | машинно-независимая (вынос вычислений из цикла) |
| 4 | `opt: column-wise pruning with carry` | Буквы перебираются по столбцам справа налево, каждый столбец проверяется сразу с учётом переноса | алгоритмическая + эвристика (раннее отсечение) |

### Почему это быстрее

- **Ведущие нули.** В базовой версии ребус проверялся только после назначения всех букв, так что значительная часть
  вариантов с нулём в начале слова отбрасывалась слишком поздно. Теперь такие ветки не создаются.
- **Веса букв.** Раньше `check` для каждой перестановки заново разбирал строки и собирал числа цифра за цифрой.
  Теперь вклад каждой буквы известен заранее (например, `D` в `SEND + MORE = MONEY` имеет вес `1 + 1 - (-0)` в разряде единиц),
  и проверка — это сумма `Σ вес·цифра == 0` без работы со строками.
- **Столбцы с переносом.** Как только все буквы очередного столбца назначены, проверяется `(сумма + перенос) % 10 == цифра результата`.
  Неверный выбор цифр в младших разрядах отсекается сразу, а не после перебора всех остальных букв.
  Поэтому число проверяемых комбинаций падает на порядки.

## Результаты

Сборка `gcc -O0`, файл `tests.txt` (9 ребусов), среднее по 20 запускам, суммарное время `TOTAL`:

| Версия | TOTAL, мс | Ускорение к предыдущей | Ускорение к базовой |
|--------|-----------|------------------------|---------------------|
| v1: базовая (исправленная) | 817.45 | — | 1× |
| v2: отсечение ведущих нулей | 652.65 | 1.25× | 1.25× |
| v3: веса букв | 426.95 | 1.53× | 1.9× |
| v4: проверка по столбцам | 1.00 | ≈427× | ≈817× |

Примечание: в версии v4 время измеряется на пределе разрешения `clock()`, поэтому значение 1.00 мс приблизительное;
для более точного замера нужно увеличить число повторов `repeats`.

## Вывод

Микрооптимизации (v2, v3) дали ускорение в 1.25–1.5 раза. Основной выигрыш (в сотни раз) дало изменение самого алгоритма:
вместо полного перебора всех перестановок с проверкой в конце, решение строится по столбцам и сразу отбрасывает невозможные ветки.
